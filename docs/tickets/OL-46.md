## Description

The shortest path to a usable tool: create an OCR project, upload page images, let a background
OCR service draft word boxes and text, and correct them on a canvas. Slices of OL-11, OL-13,
OL-14, OL-20, OL-21, OL-23, OL-24 and OL-26, built end to end; those tickets keep the remaining
scope.

## Acceptance criteria

- [x] Create a project (name, task type) inside the active organisation; list projects
- [x] Upload images (drag and drop, many at once) to object storage; sha256 de-duplication per project
- [x] Background pre-labelling: a worker picks up new assets, calls an OCR service over HTTP (`POST /predict`), stores the canonical result as a prediction; retries on failure; survives restarts
- [x] OCR service container (docTR, CPU) implementing the `/predict` contract; replaceable by any engine
- [x] Asset list with status (new, pre-labelling, ready, labelled) and progress
- [x] Canvas editor: zoom/pan, word boxes from the prediction, select/move/resize/draw/delete, edit text, keyboard shortcuts, save as a versioned annotation
- [x] All data access through the org-scoped layer; tests for it

## Technical notes

- Queue: Postgres table with `FOR UPDATE SKIP LOCKED` claiming (any number of workers, ADR-0005); pg-boss can replace it later behind the same interface.
- Editor: react-konva. Boxes stored in original image pixels (`imageAnnotationSchema`).
