## Description

Define the task-type plugin interface (annotation schema, editor, prediction contract, engine adapters, matcher, metrics, exporters) and a registry, so projects pick a task type such as image.classification, image.detection, document.ocr or audio.transcription.

## Acceptance criteria

- [x] Plugin interface in packages/contracts with a typed registry
- [x] Project stores modality + task type; unknown task types are rejected
- [x] OCR is registered through the same interface as every other task
- [x] Contract test suite that every plugin must pass

## Technical notes

- See ADR-0004 (task types) and ADR-0005 (scaling).
- `packages/contracts/src/tasks`: `defineTaskType`, `TaskTypeRegistry` (validates on register, typed `UnknownTaskTypeError`), built-ins: document.ocr, document/image/audio/text.classification, image.detection, audio.transcription, text.ner.
- `@openlabel/contracts/testing`: `taskTypeContract(def)` — runner-agnostic checks third-party plugins reuse.
- `parseCreateProjectInput` rejects unknown task types and derives modality from the task type.
- DB: `projects.task` holds the task-type id; CHECK `projects_task_type_matches_modality` (migration 0002); test keeps the modality enum equal to `MODALITIES`.
- Editors, matchers/metric implementations and exporters are looked up by the same id; they land with OL-41..OL-43 and OL-31.
