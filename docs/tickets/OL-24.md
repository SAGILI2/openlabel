## Description

Append-only annotation versions and a pull-request style review: the labeller sends a page for review and
picks reviewers; reviewers approve, request changes or comment; the page is approved once enough reviewers
approve its current version. Work is autosaved as a draft so nothing is lost, and sending for review is an
explicit final step.

## Acceptance criteria

- [x] Every save creates a new version (append-only)
- [x] Autosave as a draft about 1.5 s after the last change; no "unsaved changes" when nothing changed (ticking a word as checked doesn't dirty the page)
- [x] Submit for review is a separate, explicit step; resubmit after changes are requested
- [x] Reviewers picked per page like on a pull request, plus project default reviewers ("code owners")
- [x] Approve / Request changes (reason required) / Comment, with history on the page
- [x] Approvals pinned to the annotation version: editing the labels makes earlier approvals stale
- [x] Project review rules: required approvals (1–5), allow approving your own pages (off by default)
- [x] Only reviewer, manager, admin and owner roles can review or be requested
- [x] Exports take approved pages only by default; "Approved + waiting for review" is opt-in
- [x] Project and file browser counts show approved and in-review pages; filters for In review and Approved
- [ ] Compare two versions (follow-up)

## Technical notes

- Tables `review_requests`, `reviews`, `project_default_reviewers`; `projects.required_approvals`, `projects.allow_self_approval`; `assets.submitted_by_user_id`, `assets.submitted_at` (migration 0007).
- `reviewAsset` rejects a verdict on an outdated version with CONFLICT, so a reviewer never approves labels they didn't see.
