## Description

Turn labelled pages into training data. An export pins the exact annotation version of every
labelled asset in a project (a frozen snapshot), assigns each asset to train/val/test, and a
background job writes the chosen format as a ZIP in object storage for download. Slices of
OL-27 (snapshots), OL-28 (exporter interface) and OL-29 (first exporters); those keep the rest.

## Acceptance criteria

- [x] Export pins annotation versions; later edits don't change an existing export
- [x] Split by asset (never by word), deterministic from a seed; percentages configurable
- [x] Formats: docTR recognition (word crops + labels.json per split), docTR detection (pages + boxes), JSONL (one page per line), COCO (word boxes)
- [x] Crops are cut from the original image in original-pixel coordinates (no re-detection), with optional padding
- [x] Runs as a queued worker job; status and download in the UI; ZIP stored in object storage
- [x] Exporters are registered by id and run through a shared contract test

## Technical notes

- `packages/exporters`: format writers as pure functions over an in-memory snapshot + an image loader.
- Crops: sharp (Apache-2.0) in the worker; ZIP via fflate (MIT).
- MVP assembles the ZIP in memory before storing; switch to S3 multipart upload when exports grow past a few hundred MB.
- The split seed is the project id, so re-exporting keeps each page in the same split.
