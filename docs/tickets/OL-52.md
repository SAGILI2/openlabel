## Description

Projects with tens of thousands of files (the user's bank-slip dataset is 80,245 images) froze
the browser and took hours to pre-label on CPU.

## Acceptance criteria

- [x] OCR on an NVIDIA GPU via `docker-compose.gpu.yml` (CUDA 12.8, works on RTX 50-series); same words as CPU on a sample slip; ~0.2 s vs ~17 s per page
- [x] File list is filtered, sorted, searched and paged in the database; page-number navigation with first/prev/next/last, jump to page and rows per page (50/100/200/500)
- [x] Search by file name (as you type) and sort by oldest, newest, name A–Z / Z–A
- [x] Long folder lists render in batches as you scroll
- [x] Folder tree stays fixed while the file list scrolls
- [x] Delete a folder with its sub-folders, files, labels, reviews and OCR drafts (confirm dialog shows the count); delete selected files; unused images removed from storage
- [x] Uploading a folder puts its contents in place (no extra wrapper folder); file names no longer include the folder path
- [x] Big uploads don't freeze the page: progress throttled, failures capped, list refreshes every few seconds, Stop button
- [x] Labelling screen loads only the pages around the current one (counter shows e.g. 610/1,996)

## Activity

- 2026-10-07: implemented and verified in the browser with 2,000 slips from the dataset: upload kept 500 sub-folders, list paged 17 × 100, search "EOD_CB" → 498 results, sort by name, delete folder with 4 files, labelling page at 610/1,996. GPU OCR measured at 309 pages/minute. Status in-review.
