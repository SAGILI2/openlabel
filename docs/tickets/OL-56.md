## Description

Fixes found while labelling bank slips, plus the tooling to fine-tune docTR's PARSeq recognizer
for Hindi/Devanagari. The Hindi model is opt-in (`OCR_RECO_CHECKPOINT`) and off by default: a
single mixed Hindi+English recognizer wrote Devanagari vowel signs into English words, so it isn't
enabled until Hindi gets its own recognizer behind script detection.

## Acceptance criteria

- [x] A page whose saved draft has no boxes left shows the latest OCR reading instead of an empty draft
- [x] "Re-run OCR on this page" in the editor top bar (high priority; saved labels kept)
- [x] "Discard draft" resets the page to the latest OCR reading as a new version (history kept)
- [x] The link from the selected box to its word follows selection changes and box nudges, not only pan/zoom/scroll
- [x] ← / → move to the previous / next word; ↑ / ↓ to the nearest word in the line above / below; Ctrl+arrows nudge a box
- [x] OCR service loads an optional fine-tuned PARSeq checkpoint (`OCR_RECO_CHECKPOINT`), validated at start
- [x] Hindi training pipeline: data builder (IIIT-INDIC-HW-WORDS-Hindi CC BY 4.0 + synthetic printed words), multi-GPU trainer, evaluator, Kaggle background-run builder
- [ ] Hindi recognizer used only for Devanagari words (script routing), so English accuracy can't regress
